# Q のツールのファイルの並べ方と名前

どのツールを開いても、同じ名前のファイルに同じ役わりがあるようにするための決まりです。新しいツールは最初からこの形で作り、今のツールは手を入れるときにそろえます。
使い心地の決まりは [ux.md](ux.md)、共通の部品は [README の「Q キット」](../README.md#q-キットq-のツールの共通部品) にあります。

## ページ（GitHub Pages のツール）

| 名前 | 役わり |
|---|---|
| `index.html` | 使う画面。ページが2つあるときは、作る画面を `create.html`（受けとった人が見るほうを `index.html`） |
| `app.js` | 画面の入口（1ページに1つ）。部品をつないで、ボタンや入力を受ける。`create.html` の入口は `create.js` |
| `style.css` | 見た目（1ページに1つ）。大きくなったら `css/○○.css` に分けて、`style.css` から `@import` |
| `js/○○.js` | 役わりごとの部品。名前は小文字の英語、2語以上は `-` でつなぐ（`place-name.js`） |
| `data/○○.json` | 決まった中身（お題・市区町村の表など） |
| `sw.js`・`manifest.webmanifest` | 電波がないときに開く仕組みと、ホーム画面に置くときの設定（`manifest.json` にしない） |
| `test/○○.test.js`（`.mjs`） | テスト（`node --test test/`） |
| `tools/○○.py` | 画像や表を作る道具（公開するが、ページからは読まない） |
| `docs/○○.html`・`privacy.html` | 手順書・LINE の情報の使い方 |
| `README.md` | 何のツールか・ファイルの一覧・公開のしかた |

### `js/` の名前（同じ役わりは、どのツールでも同じ名前）

| 名前 | 役わり |
|---|---|
| `store.js` | 端末に残すもの（localStorage）の読み書きと形の確かめ |
| `card.js` | 送るカード（Flex・おくるんのお知らせカード）を作る |
| `link.js` | URL の受け渡し（ほかのツールへのリンク・受けとったリンクを読む・共有リンク） |
| `stats.js` | 数える・まとめる（何日つづいた・合計など） |
| `line-config.js`・`linelog.js` | LINE 版のつなぎ先の設定（LIFF の ID）と、そのツールがボットに頼むこと（送る中身・ボットの言葉の読みかえ）。つなぐ・送る・送りなおす・LINE 版の案内は Q キットの `shared/botlink.js`（`window.QBotLink`）を使い、ツールに写さない |
| そのほか | ツールにしかないものは、中身を表す名詞で（`meteo.js`・`board.js`・`draw.js`） |

- 使わない名前：`main.js`・`script.js`・`common.js`・`utils.js`・`core.js`（何が入っているかわからない）。中身に合わせて分けるか、`app.js` にまとめる
- ページの直下に部品を置かない（`calendar.js`・`params.js` は `js/` の中へ）

### 名前を変えるとき

- 部品（`js/` の中）は、読む側の `import` もいっしょに変え、`?v=` を前より大きい値にそろえる（[tools/qstamp.py](../tools/qstamp.py)。今ある番号より必ず大きい値を付ける。小さくなったら `tools/qtest/check-code.mjs` の V1 で止まる）
- HTML から読むファイル（`app.js`・`style.css` など）の名前を変えるときは、LINE の中のブラウザが古い HTML を覚えていることがあるので、前の名前のファイルを1か月ほど残す（新しいファイルを読むだけの短い中身にする）。消す日を README に書く
  - ES モジュールは `import "../app.js";`、CSS は `@import url("../style.css");` の1行でよい
  - 順に読む普通の `<script defer>`（おくるんの `card/js/` のように、いくつものファイルが同じ範囲の変数を使うもの）は、短い中身では読む順を保てないので、新しいファイルの写しを置く
- `sw.js` の覚えるファイルの一覧も直す
- 公開している URL（`index.html`・`create.html`・`privacy.html`・`docs/` の手順書）の名前は変えない

## コメント（ページも GAS も）

- **ファイルの先頭に必ず**：このファイルは何のためか・中に何があるか・どこから読まれる（呼ばれる）か を数行で。GAS の `00_` のファイルは、それに加えて「どの順に何を実行するか」
- **関数の前に必ず**：何をするか（と、返すもの）を1〜2行で。人がエディタから実行する関数は「いつ実行するか・実行するとどうなるか」も。中で使うだけの短い関数も省かない
- 言葉は短く、ふつうの日本語で。コードを読めばわかる「何行目で何をしているか」は書かない。直したいきさつ（いつ・だれが）は書かず、コミットに書く
- 名前を変えたり分けたりしたら、コメントも合わせて直す（古いファイル名・関数名を残さない）

### 中にページがいくつもあるツール（おくるん）

- ページごとのフォルダ（`card/`・`plan/`・`image/`…）の中で、上と同じ形にする：`index.html`・`app.js`・`style.css`・`js/○○.js`
- サイトのトップのページも同じ（`index.html` の中に長い `<style>`・`<script>` を書かず、`style.css`・`app.js` に）
- 全ツールが読む共通の部品は `shared/`（URL で読まれているので、名前は変えない）

## GAS（LINE のボット）

- ファイルは「番号＋役わり」で、読みこむ順がわかるように（例：`01_config.js`・`02_entry.js`）。1つのリポジトリの中でそろえる
- **人が実行する・よく見るものを上に**：エディタのファイルの一覧も「実行」の関数の一覧も、名前と書いた順に並ぶので、
  - `00_` のファイルに、人がエディタから実行する関数（はじめの準備・自己点検・持ち主の登録・#テストの見本・版の確かめなど）と、人が書きかえる設定だけを置く。いちばん上に「どの順に何を実行するか」を短く書く
  - その中も、よく使う順（自己点検 → 準備 → めったに使わないもの）に並べる
  - 中で使うだけの関数は名前の最後に `_` を付けて、「実行」の一覧に出さない（GAS は `_` で終わる関数を一覧に出さない）
  - ただし、トリガー・`google.script.run`・ライブラリとして入口から呼ばれる関数・メニューに登録した関数は、名前を変えると動かなくなる（`_` の関数はライブラリの外から呼べない）。変える前に呼ばれ方を探し、トリガーは付けなおす
  - トリガーやボットから呼ばれる入口（`doPost`・時間の関数）は `00_` のすぐ下（`01_`）に
- 共通の部品は、どのボットでも同じ名前：`season.gs`（季節の絵文字。q-oqrn の `shared/season.js` の写し）・`selfcheck.gs`（自己点検。`tools/qtest/selfcheck.gs` の写し）
- 写しの中身は元と同じにする（テストで確かめる）。元を直したら `node tools/sync-copies.mjs` で写しがちがっていないか見て、`--write` でそろえる（写しの一覧はこの道具の COPIES。新しく写したら足す）。そろえたら、それぞれのリポジトリでコミットし、GAS は次に出すときに `clasp push`
