# Q のツールのセキュリティの決まり

コネクト〜ConneQt〜の Q のツールと、これから Q に入れるツールで、守ること・確かめることです。
番号は、`tools/qtest/check-code.mjs` が出す目印と同じです。

**見つけた穴は、直すまでこのリポジトリ（公開）に書かない。** ふさいでから、何をどう直したかをコミットに書く（どう悪用できるかまでは書かない）。

役割は3つに分けて考えます：**システム管理者**（GAS のデプロイ・Script Properties・LINE の鍵）、**ツール管理者**（管理者だけの操作・プランの一覧）、**ユーザー**（ふつうに使う人）。どの操作を、だれができるかを先に決めます。

---

## W. 画面（GitHub Pages・LIFF）

- **W1 文字を HTML に入れるときは esc する**：`innerHTML`・`insertAdjacentHTML` に入れる文字は、自分で書いた決まった文字以外、かならず `esc()` を通す。URL の中身・端末に残した中身・サーバーの返事・ほかの人が作ったカードの中身は、すべて「外からの文字」。できれば `textContent` を使う
- **W2 文字をプログラムとして動かさない**：`eval`・`new Function`・`setTimeout("文字")` を使わない
- **W3 別のタブで開くリンク**：`target="_blank"` には `rel="noopener"`
- **W4 読むプログラムは決めた所から**：script は https で、決めた所だけ（katsuan.github.io・LINE・jsdelivr・unpkg・cdnjs・Google・Stripe）。版を決めて読む（`@1.2.3`）
- **W5 よそへ飛ばさない**：URL の中身で別のサイトへ移らない。移る先は、自分のツール（katsuan.github.io）か、決めた所だけ
- **W6 よそのページからの知らせ**：`postMessage` を受けるときは、送り主（`event.origin`）を確かめる
- **W7 端末に鍵を残さない**：ID トークン・アクセストークン・合言葉を localStorage に残さない（覚えるのはその場かぎり）。端末に残すのは、その人の作ったもの・設定だけ
- **W8 ブラウザの小窓を使わない**：`confirm`・`alert`・`prompt` は使わない（[ux.md の D3](ux.md)。LINE の中では、上にドメイン名が出て見分けにくい）
- **W9 URL で渡す中身**：`?data=` などで受け取る中身は、形・長さ・数の範囲を確かめてから使う（例：お知らせカードのサッカーの中身）。個人の情報（名前・誕生日など）を URL に入れるときは、そのリンクを送った人だけが見る前提で、検索に出ないページ（`noindex`）にする
- **W10 公開する鍵**：画面に置いてよい鍵は、置く前提の鍵だけ（LIFF ID、HTTP リファラーで制限した Google Maps の鍵など）。制限のない鍵・秘密の鍵は置かない

## G. GAS（ボット・API）

- **G1 シートに外の文字を書くときは safeCell**：LINE や画面で入れた文字（名前・メモ・メニュー名など）は、`=` `+` `-` `@` で始まると、シートを開いたときに式として動く（よそへ中身を送る式も作れる）。シートに書く前に `safeCell()`（`tools/qtest/selfcheck.gs`）を通す。数・日付・決まった文字はそのままでよい
- **G2 エラーの中身を出さない**：画面・LINE に返すのはやさしい言葉だけ。エラーの中身は、管理者だけが見られるところ（実行ログ・`LAST_LINE_ERRORS` など）に
- **G3 だれが呼べるかを決める**：`doPost` の入口で、呼び方ごとに分ける
  - LINE の Webhook：URL の合言葉（`?key=`。値は Script Properties の `WEBHOOK_KEY`。GAS は LINE の署名を読めないため）
  - 画面からの呼び出し：LIFF の ID トークンを LINE に確かめて本人を決める（**G4**：画面から送られた userId は信じない）
  - 管理者だけの操作：確かめた本人が、管理者の一覧（Script Properties）にいるときだけ。管理の画面を開けても、中身は管理者にしか返さない
  - だれでも呼べてよいもの（`health` など）は、個人の情報を返さない
- **G5 鍵は Script Properties に**：LINE の鍵・Stripe の鍵などはコードに書かない。`.clasp.json` は git に入れない（`.clasp.json.example` を置く）
- **G6 入る文字の長さと数**：外から来る文字・まとめて送る数に上限を決める（例：名前 60 字、まとめて記録は 30 件まで）。上限をこえたら切るか断る
- **G7 同時に書く**：同じ行を何人もが同時に書きかえるところは `LockService`
- **G8 ライブラリの開発モード**：入口の GAS がライブラリを開発モードで読む作り（食事記録・KazoQ・学習）は、ライブラリに `clasp push` した瞬間に本番が変わる。送る前に、別の場所に `clasp pull` してエディタだけの直しがないか比べ、テストを通してから
- **G9 公開の範囲**：ウェブアプリは「全員（匿名を含む）」にしている（LINE と画面から呼ぶため）。そのぶん G3 の確かめを入口でかならずする
- **G10 送りすぎない**：push（LINE の月の上限がある）は、ユーザーの操作1回につき1回まで。まとめて送るときは最後に1回

## S. どちらも

- **S1 鍵をリポジトリに入れない**：コミットの前に `check-code.mjs` で探す。入れてしまったら、消すだけでなく鍵を作りなおす
- **S2 使う人の情報**：集めるのは使う分だけ。LINE のユーザー ID をそのまま記録・ログに出さない（数えるだけなら SHA-256 にする。おくるんの利用状況と同じ）
- **S3 依存する外のもの**：GitHub Actions の action・npm の版は決めて使う

## 確かめ方（ツールごと）

1. `node ../q-oqrn/tools/qtest/check-code.mjs .` を動かし、出た目印を1つずつ見る。問題ないものは、その行に `// qcheck-ok: <番号> <理由>`
2. GAS は `tools/qtest/fake-gas.js` でテストを書く（使い方は `tools/qtest/README.md`）：
   - だれが呼べるか（本人確認なし・ちがう人・管理者でない人が断られる）
   - 外の文字がシートに式のまま入らない（`gas.formulaCells()` が空）
   - 返事のカードが LINE に受けつけられる形（`gas.flexProblems()` に error がない）
3. GAS のプロジェクトに `tools/qtest/selfcheck.gs` を入れ、`Q_SELF_CHECK` を書いて、使う前に GAS エディタで `qCheckAll` を動かす
4. 画面は、外からの文字（URL の中身・端末に残した中身）に `<img src=x onerror=alert(1)>` のような文字を入れて開き、そのまま文字として出ることを見る
