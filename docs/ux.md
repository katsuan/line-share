# Q の使い心地の決まり（くらぶ〜Qlove〜の UX・UI）

くらぶ〜Qlove〜の Q のツールと、これから Q に入れるツール（勉強クイズくん・食事記録・ほかの LINE ツール）が、どれを開いても同じように使えるための決まりです。
ファイルの並べ方と名前は [structure.md](structure.md)。部品（見た目と動き）の使い方は [README の「Q キット」](../README.md#q-キットq-のツールの共通部品) にあります。ここには「どんな場面で、どう振る舞うか」を書きます。

番号（`A1` など）は、ツールごとに確かめるときの目印です。決まりと違うことをするときは、そのツールの README に理由を書きます。

**対象外**（決まりに合わせない）：ぽもくるの英語の表示（work・break・Volume など）と、ロゴを設定の中だけに置くヘッダー。ジェンダーリビールの Q の名前（決まるまでそのまま）。Rct（Q には入れない）。

---

## A. 名前と見た目

- **A1 見出しの行**：アイコン＋名前（左）、横長のロゴ（右）、その下にキャッチコピー1行（`ls-brand`・`ls-brand-copy`）。横長のロゴを押すと、そのツール自身の紹介のシート（紹介画像・キャッチコピー・説明・「カードでおくるん」。自分自身なので「開く」はなし。`tool-share.js` が付ける）。名前はひらがな・カタカナ（例：しょくじ）、英字（例：ShoQuji）はロゴと紹介にだけ使う。LINE 版（LIFF）で開いたときは、ロゴの右に本人の LINE のアイコン（`shared/line-me.js`。写真がないときは名前の頭の字を、名前で決まる色の丸に。同じ名前なら、どのツールでも同じ色）。緑のふちはログイン中、緑の点線は前回のログインのまま（電波がないなど。もどったら確かめる）、灰色はまだ（押すと「🔑 LINE でログイン」）。まだボットに送っていない記録があれば、右上にオレンジの数。押すと、だれでログインしているか・ボットとのつながり・ブラウザ版との記録のちがいのシート
- **A2 色と字**：ツールの色は1色（`--ls-accent`。濃い色・薄い色・文字色はそこから）。字は Q キットの書体かツールの書体を `--ls-font` で。色を変えられるツール（くろのす・キロっく）は、選んだ色を `--ls-accent` につなぐ
- **A3 暗い表示**：`<html data-ls-dark="auto">`。LINE のトークの見た目（送る前のプレビュー・カードの見本）と、受け取った人が見るお祝いのページは明るいまま
- **A4 部品**：カード・チップ・入力欄・ボタン・開閉・タブ・シート・トーストは Q キットのもの。ツールにしかない見た目（盤・グラフ・こまなど）だけ、ツールの CSS に置く
- **A5 いちばん下**：「○○を紹介する」（頭におくるんのマーク）と くらぶのアイコン列（`tool-share.js`）。ページの最後に1つだけ
- **A6 公開の前**：確かめが済むまで `noindex`、くらぶの一覧とポートフォリオに載せない。アイコン・OGP・`manifest` をそろえる
- **A7 設定の置き場所**：設定（週のはじまり・表示・目標・記録の控えなど）は、ページの下（「○○を紹介する」の上）の「設定」のたたみ欄（`id="settings"`）に1つにまとめる。週のはじまりは Q 共通の設定（`shared/week-start.js`。はじめは月曜、端末に1つだけ残し、どのツールで変えてもほかのツールも同じになる）を使い、どのツールもここに置く。LINE 版はアイコンのシート（`line-me.js`）の「⚙️ 設定」からここへ（`QLineMe.openFold("settings")`）。ボットとつなぐ欄は「🔗 ○○とつなぐ」で別に

- **A8 説明の文の折り返し**：説明の文（`p`・`li`・`.ls-hint`・`.ls-empty`・`.ls-tip`・○○-lead など）は、ふつうに行のはしまで使って折り返す。文節で折る `word-break: auto-phrase` と、行の長さをそろえる `text-wrap: pretty` は付けない（iPhone の Safari ではどの行も早めに折れ、枠の右に大きな余白ができる。2回起きた）。文節で折る・`balance` は、見出し・ラベル・ボタンだけ。`tools/qtest/check-code.mjs` の V2 で止まる
- **A9 版の番号**：読みこむ URL の `?v=` は、公開のとき（GitHub Actions の `q-pages.yml` → `tools/qpublish.py`）に、全ファイルそろえて前より大きい値に付け直す。**JS・CSS を変えても、repo の中で手で上げなくてよい**（古いファイルが残って画面が出なくなるのを、公開のしくみが防ぐ。前は手で上げていて3回起きた）。repo の中の `?v=` は下げない（`check-code.mjs` の V1 で止まる）

## L. 見た目（落ち着いた画面。2026-11 から）

AI で作ったような、にぎやかな見た目にしない。番号は `tools/qtest/look.mjs` の数え方と同じ（直す候補の数を出すだけで、止めない）。見本は `shared/kit.html` の「見た目の決まり」。

- **L1 平らな地**：背景・ボタン・見出しにグラデーションを使わない。地は `--ls-bg`・`--ls-surface`・`--ls-surface-sub` の3段。影（`box-shadow`）も付けない（`--ls-shadow` は `none`）。枠の線と地の濃さで分ける。透明を表す市松模様、横に流れる帯の端をぼかす `mask` はよい
- **L2 8 の倍数**：余白と間は `--ls-space-s` 8・`m` 16・`l` 24・`xl` 32・`xxl` 48。`xs` 4 は、アイコンと字の間など細かい所だけ。ページの左右とパネルの中は 16、並んだ部品の間は 8、かたまりの間は 16〜24。角の丸みは `--ls-radius-sm` 8・`md` 12・`lg` 16 と、丸いボタンの 999px
- **L3 文の頭をそろえる**：シート・カード・案内・見出し・空のときの一言・ボタンの並びは左そろえ。中央は、数字だけの大きな表示（残り時間・得点）、ボタンの中の文字、送る前のプレビューのカード（LINE と同じ見た目）だけ
- **L4 線アイコン**：ボタンの印は G3 のとおり線アイコン。ボタンでない、前に決めた印（目じるしの表の ✅・お知らせカードの形式の 📣🗳️・たたみ欄の頭の絵文字など）を替えるときは、ツールごとに確かめてから。画面の印は Q キットの線アイコン（`shared/icons/`。Lucide、ISC ライセンス）。HTML は `<span class="ls-icon" data-icon="send" aria-hidden="true"></span>`、JS は `LineShareUI.icon("send")`、CSS は `mask: var(--ls-i-send)`。文字の色・大きさで出る（ボタンの中は字の前、間は 8）。LINE に送るカードの中身・ボットの文・遊びの絵（盤・コマ・演出）は、いまは絵文字のままでよい（下の「まだ決めていないこと」）
- **L5 強弱は濃淡**（選んでいるチップは濃いふちと字。2026-11-05 に決めた。ls-pickfield・大きさの mega の印は、前に決めたツールの色のまま。変えるかは決める）：目立たせるのは、字の濃さ（`--ls-text`・`--ls-subtext`・`--ls-faint`）と太さ（400・600・700。800 以上は使わない）。選んでいるチップ・色見本・入力中の枠は、濃い字の色のふち。ツールの色（`--ls-accent`）と LINE の緑は、送るボタンなど、いちばん大事な1か所だけ。キャッチコピー・見出し・説明には色を付けない
- **L7 アイコンは字になじませる**：線アイコンの色は `currentColor`（となりの字と同じ。ツールの色のボタンの中なら白、うすい字の中ならうすく）。アイコンにだけ色・濃い色・グラデーションを付けない。大きさは 1em（大きくするときは `font-size`）、上下は字の並び（Q キットが `vertical-align: -0.125em`）。線は Lucide の 2 のまま（1em で 600〜700 の字の太さに近く、小さい字では線も細くなる）。アイコンだけのボタン（`ls-icon-button`）も色で目立たせず、押せることは形（枠）と押せる広さ（44px）で伝える。開閉の矢印・「次へ」の矢印だけは印なので、うすい字の色でよい
- **L6 むだな見出しを置かない**：説明のくり返しになる見出し（「使い方」の案内の「💡 使い方」など）、中身が1つしかない見出しは外す。読み上げに要るときは `aria-label` に

**ツールを直すときの点検**（上から）

1. `node ../q-oqrn/tools/qtest/look.mjs .` で L1〜L6 の数を見る（`--list` で何行目か）
2. グラデーション・影を、平らな色に
3. ツールの CSS の余白を `var(--ls-space-…)` に、角を `--ls-radius-…` に
4. `text-align: center` を外す（大きな数字・ボタンの中だけ残す）
5. ボタンの絵文字（G3）と、決めていない所の絵文字を線アイコンに（足りない形は `tools/icons.py` の説明のとおり足す）。**わざと入れた見た目・言葉・色・並び・印は変えない**：コミットの履歴・docs・README・ux.md で決めたものか調べ、決めたものは「変えてよいか」の一覧にして聞く
6. `--ls-accent` を使う所を減らす（選んでいるもの・決めた部品の色は残す）
7. 見出しを1つずつ見て、なくても通じるものを外す
8. 320px の幅と暗い表示で、前と後をくらべる（1文字だけの行・はみ出しがないか）

**まだ決めていないこと（案）**

- 遊びの中身（ひっくりの盤・コマ、くじの演出・くじの種類のボタン、ろくがの得点板）：盤やコマは「絵」なので絵文字・色のままにし、そのまわりのボタン・見出し・案内だけ L1〜L6 にそろえる案。くじの種類（🎟️ くじびき・🪜 あみだ…）は線アイコン（ticket・list など）に変える案と、楽しさのために残す案
- キロっくの目じるしの動物（🐼 パンダ・🐘 ゾウ…）：重さをくらべる「中身」なので残す案。表の行の頭の印（越えた・次・鍵）はもう線アイコン
- LINE に送るカード・ボットの文の絵文字（「✅ 準備できた」・季節の絵文字・おくるんのキャッチコピーの 💬）：受け取る人が見るもので、LINE ではよく使われるので、いまは残す。減らすなら、カードの見出しだけ外す案
- お知らせカードの見出しの色（2色のグラデーション）：送るカードそのものの見た目なので、平らな1色にするかは別に決める
- 季節の絵文字（`shared/season.js`。おくるんのトップの説明のあとに1つ）：飾りなので外す案と、季節を感じるので残す案

## B. 開いたとき

- **B1 すぐ出す**：前に開いたときの中身（端末に残したもの）を先に出し、ネットの返事はあとから重ねる。返事を待つあいだ真っ白にしない
- **B2 読みこみ中**：中身と同じ大きさの箱（`ls-skeleton`）か、ボタンの中の「○○中…」。位置がずれない形で。3秒をこえるものは経過秒数と理由（`LineShareUI.progress`）
- **B3 はじめての人**：使い方を3つまで、1回だけ（`LineShareUI.firstTip`。「わかった」で消え、その端末では二度と出さない）。説明の文をページに置きっぱなしにしない
- **B4 前回の続き**：作りかけは端末に残し、次に開いたら「前回の続きから開きました［新しく作る］」
- **B5 電波がないとき**：`sw.js`（`shared/sw-core.js`）で開けるように
- **B6 LINE の外で開いたとき**：送れないことより、次にすること（「ログインして送る」「LINE 版で開く」）を、送るボタンの上に短く。エラーにしない（例：「ここでは見本だけ。送るときは LINE 版で」）

## C. 入力

- **C1 iPhone**：入力欄は 16px 以上・`appearance: none`・並べるときは `minmax(0, 1fr)`、`html` にも背景色、ぼかし（`backdrop-filter`）は使わない
- **C2 キーボード**：数字は `inputmode="numeric"`／`decimal`、`enterkeyhint` を付ける。入力中は下の送る帯を隠す（Q キットが自動で）
- **C3 選ぶもの**：選んでいるものは `aria-pressed`（`role="radio"` なら `aria-checked`）。押せるところは 44px 以上
- **C4 先に入れておく**：前に入れたもの・よく使うものを、押すだけで入るボタンで出す（例：しょくじの「よく食べるもの」、食事記録の「よく記録するもの」）
- **C5 その場で知らせる**：足りない・まちがいは、その欄のすぐ下に赤い文字で（送ってからまとめて出さない）

## D. 消す・やり直す・確かめる

- **D1 1つを消す**：確かめずにすぐ消し、トーストの「元に戻す」で戻せる（`LineShareUI.toast(…, { actionLabel: "元に戻す", onAction })`）。呼び方は「元に戻す」にそろえる（「取り消す」は使わない）
- **D2 大きな操作**：全部消す・上書きなど元に戻せないものだけ、`LineShareUI.ask({ danger: true })` で確かめる。ボタンの文字は「消す」「上書きする」のように、することを書く（「OK」にしない）
- **D3 ブラウザの小窓は使わない**：`confirm`・`alert`・`prompt` は使わない（LINE の中では上にドメイン名が出る）。代わりに `ask`。コピーできないときは `ask({ readonly: true })` で選べる文字を出す
- **D4 保存の前に聞かない**：変えたらすぐ端末に残す。「保存しますか？」と聞かない

## E. 知らせ

- **E1 トースト**：うまくいった・元に戻せる、は下に数秒のトースト。新しいものが来たら前のは消える
- **E2 失敗**：何が起きたかと、次にすること（「もう一度」「LINE で開きなおす」）を、やさしい言葉で。仕組みの言葉（LIFF・API・GAS・エラーの中身）は出さない。くわしい中身は管理者だけが見られるところ（動作の記録）に
- **E3 待たせない**：保存は返事を待たずに画面に先に出し（薄く）、返事が来たら確定。失敗したら戻して知らせる

## F. 送る（LINE）

- **F1 送り方**：カードは、おくるんのお知らせカード（`OQRN.cardUrl`）か、ツールの Flex を `shareTargetPicker` で。ボタンはおくるんのマーク（吹き出しの Q）＋「カードでおくるん」で、色は LINE の緑（`ls-button line is-oqrn`。💬 は付けない）。LINE とわかるのは色に、Q のシリーズだとわかるのはマークにまかせ、言葉に LINE を入れない。「（おくるん）」の小さい字も付けない（マークでわかる）
- **F2 送る前**：送る内容をトークの見た目のプレビューで見せる。送れない理由はプレビューの上に
- **F3 送ったあと**：「続けて別のトークにも送る」「閉じる」「もう少し作る」（`LineShareUI.afterSent`）。すぐ閉じない
- **F4 カードの末尾**：「Created by ○○ ›」。押すとそのツールが開く。カードを開いたボタンの行き先は、受け取った人が使える場所（作り直す・確かめる）に

## G. ことば

- **G1** やさしい日本語。ひとつの文に、ひとつのこと。「〜してください」より「〜できます」「〜してね」
- **G2** 同じ役割は同じ言葉：「元に戻す」「カードでおくるん」（おくるんのマーク）「LINE 版／ブラウザ版」「○○を紹介する」（おくるんのマーク）「やめる」「閉じる」「なくてもOK」
- **G3** ボタンは「線アイコン＋する言葉」（例：［＋］記録する・［保存のアイコン］画像で保存。Q キットの `ls-icon`、L4）。アイコンだけのボタンには `aria-label`。2026-11 に「絵文字＋する言葉」から替えた（ユーザーと決めた）
- **G4** 説明の文は短く、必要なときだけ開いて読めるところ（`ls-fold`）に
- **G5 LINE は手段**：「何ができるか」を先に言い、LINE は前に出しすぎない
  - 名前・キャッチコピー・題（`<title>`・`og:title`）・最初の画面には LINE を書かない
  - OGP（題・画像・`og:description`・`description`・`manifest` の説明）には、LINE も中の言葉（LINE 版・記録ボット・シート・GitHub・GAS など）も書かない。「何ができるか」と「カードで送れる」で言う。LINE 版のよさは画面の中（ブラウザ版の案内）で伝える
  - 自分のボットとつなぐ欄は「○○とつなぐ（くわしい人向け）」の開閉にしまい（「設定」とは別。A7）、ふだんの流れのじゃまをしない。中身（つなぎ先の URL の入れ方・確かめ・「LINE 版で開きなおす」・ブラウザ版の「📱 LINE 版で使う」と4コマ）は Q キットの `shared/botlink.js` でそろえる
  - 画面の中で LINE と書くのは、1つの画面に1回まで（送るボタンの近くなど）
  - LINE の中（LIFF）で開いたものは「LINE 版」、Safari などで開いたものは「ブラウザ版」と呼ぶ。「LINE の中で開いたとき」「LINE の外で開いています」とくり返さない（例：「LINE 版では、記録ボットにも残ります」）
  - つなぐ設定は、つなぐ相手の名前で：「くらぶボットとつなぐ」（「LINE とつなぐ」にしない）
  - 対象外：LINE が本体のツール（おくるん・ひっくり・くるかな）の名前と説明、プライバシーの説明、「LINE で開きなおしてね」のように LINE を開くこと自体をお願いする文

## H. LINE のボット（トークで使うもの）

- **H1 待たせない**：返事に時間がかかる処理の前に「入力中…」（`/v2/bot/chat/loading/start`）。ただし返事をしない操作（リッチメニューのタブの切りかえなど）では出さない（消えずに残るため）
- **H2 カードの形**：色の帯（小さく日付・区分、太く見出し）→ 中身（大事な数字を先に）→ 行動のボタン（2つまで）。ツールの色を帯に。1通にまとめ、必要なときだけカードを足す（例：未記入があるときだけ「カロリーを入れる」）。LINE が受けつけない書き方（`#RRGGBBAA` の色・`filler`・中身の空の箱）は使わない。横に並べるカード（carousel）は、すべて同じ大きさ（`size`）にそろえる（混ぜると返事ごと断られる）。横に並べるのはよい（トークを無駄に増やさない）。LINE では、横に並べたカードはどれもいちばん縦長のカードの高さにそろうので、送る前の見本（プレビュー）も同じ高さにそろえて描く（見本と実際の見た目をずらさない）
  - **カードのボタンは、あとで押されても困らないものだけ**：カードはトークに残り、何日もあとに押されることがある。置いてよいのは、画面（LIFF）・URL を開く／聞き返すだけ（例：「入れる」→「ご飯何杯分？」と聞く）／名前を送って新しく記録する／**押されるたびにボットがいまの状態を見て返す postback**
  - **postback ならカードに置いてよい**：1回きりの操作（ルールの確認・承認など）や、特定の記録への操作でも、postback の data に「何に対する操作か」（版・記録の ID・押せる人など）を入れ、ボットが押されるたびに、もう済んだ・古い・ほかの人・期限切れを見分けて返せるなら、カードのボタンにしてよい（例：ルールの「✅ ルールを確認しました」→ 済んでいれば「もう記録しています」）。同じものをクイックリプライにも出してよい
  - クイックリプライだけにするのは、ボットが見分けられないもの：文字を送るだけ（message）で何に対する操作かがわからないもの、期限のある印をそのまま使うもの（画像の付け先など）、出題中の答えのように押した時点の画面がないと決められないもの
  - カードはトークに残るが、クイックリプライは次のメッセージで消える。カードに「👇 下のボタンから」とだけ書くと、あとで見て意味がわからない。カードの文はクイックリプライが消えたあとでも通じるように書き、押せばクイックリプライを出しなおすボタン（聞き返すだけ）か、いつ押してもよい代わりの道（画面で入れる・保存するなど）を置く
  - 古いボタン・終わった操作が押されても黙らず、「もう入っています」のようにやさしく返す
- **H10 文かカードか**：返事は次で決める（迷ったらカード）
  - **カードにする**：あとで見返すもの（記録した中身・まとめ・一覧・予定・結果）、項目が3つ以上あるもの、数字が主役のもの、次に押す道があるもの。1行の文を何通も重ねて返していたら、1枚のカードにまとめる
  - **文のまま**：ひとことの受けつけ（「やめました」など）、まちがいの知らせと直し方、聞き返し（「ご飯何杯分？」）、会話の返事。文にもクイックリプライ（H3）を付けて、次の操作を押せるようにする
  - カードにしたら、`altText` は通知とトーク一覧に出る文なので、中身がわかる1行にする（「カードが届きました」にしない）
  - ボタンは H2 の決まり（あとで押されても困らないものだけ。押されるたびにボットが状態を見て返す postback なら、1回きりの操作もカードに置いてよい）。ボットが見分けられない操作はクイックリプライ。押したら返事が来る（黙らない）ように postback かメッセージを返す
  - 打ちこむ言葉を覚えないと使えないもの（「# 設定」など）は、カードのボタン・クイックリプライ・リッチメニューから押せるようにする
- **H3 次にすること**：返事の最後のメッセージに、クイックリプライで次の操作（よく使うもの・やめる・画面で詳しく）。13個まで、ラベル20字まで。押したらそのまま終わる操作にする（「次へ」を押させてトークをあふれさせない。例：勉強クイズくんの連続出題）
- **H4 DB にないとき**：記録はしておき、「だいたい」で入れられる選択肢（例：ご飯◯杯分）と「画面で詳しく」を出す。未記入のまま放っておかない
- **H5 カードが通らないとき**：黙らない。文字だけの返事にして、管理者が原因を見られるところに残す（`LAST_LINE_ERRORS` など）。返事の合図（reply token）は1回しか使えないので、断られたあとの返しなおしは push で送る（同じ合図で reply しなおすと「Invalid reply token」でまた断られる）
- **H6 リッチメニュー**：タブは2つまで（例：「📝 記録」と「⚡ よく記録」、「ふだん用」と「出題中用」）。押すとすぐ記録できるものは、ユーザーごとのメニューに。画像の文字は 2500×1686 で読める大きさ
- **H7 送り主**：`sender` の名前とアイコンで、どの機能からの返事かを分ける（増やしすぎない）
- **H8 管理者**：管理者だけの操作（問題の登録・承認など）は、ふつうの人には出さない。見本の文は「入力欄に入れる」（`inputOption: openKeyboard` と `fillInText`）か「コピー」で
- **H9 返事を速く**：1回の呼び出しの中で、同じシート・設定は1回だけ読む（`memo_`）。本人確認などの外への問い合わせは覚えておく
- **H11 管理者のテストの窓口**：管理者だけが、トークで「#テスト」（ひらがな・全角の＃も。`#test` は、そのボットにすでに別の意味の言葉がなければ）と送ると、🧪 テストのカードが返る。ふつうの人が送っても何も変わらない（知らない言葉と同じ返事。窓口があることを見せない）
  - 「🩺 自己点検」（共通の `selfcheck.gs` の `qCheckAll`。KazoQ は `#qHealth` も）には、今月の送信数（「今月 ◯ 通 ／ 上限 ◯ 通（のこり ◯）」。8割をこえたら ⚠️、上限で ❌）が出る。読むだけで何も送らない。鍵の名前は各ボットの `Q_SELF_CHECK.lineTokenProperty`
  - カードから押すだけで試せるようにする：①返事・カードの見本を全部（中身はためしのデータ）②自己点検（`qCheckAll` など。設定・シート・トリガーのようす）③カードが断られたときの文の返事（H5）④季節の絵文字の出る・出ないの両方。選ぶのはクイックリプライかボタン（押したら返事が来る）
  - 本物の記録・シート・GitHub・ほかの人には書かない、送らない。見本の返事にはすべて「🧪」を付け、本物とまぎれないように
  - 返事（reply）だけで返し、push（無料枠を使う知らせ）は使わない。決めた時間の知らせなど push のものは、見本を reply で見せる
  - 管理者かどうかは、今の管理者の決め方（システム管理者・ツール管理者の分け方）をそのまま使う

## I. ウィジェット（SQriptable）

- **I1** 小さな画面で、数字や名前を先に。説明は入れない
- **I2** 読めないとき（ネットがない・データがない）は、前の中身を薄く出し、「—」で埋める。エラーの文を出さない
- **I3** 押すとそのツールが開く

## ツールごとの確かめ方

1. このページの番号を上から見て、合っていないところを直す（できないものは README に理由）
2. スマホの幅（390px と 320px）で開き、明るい表示と暗い表示の両方で見る。コンソールのエラーがないこと
3. 主な操作を1通り（作る・直す・消して元に戻す・送る・LINE の外で開く）
4. ボットは、主な返事を偽物の LINE で動かし、カードの形（H2）とクイックリプライ（H3）を見る
