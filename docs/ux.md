# Q の使い心地の決まり（ConneQt の UX・UI）

コネクト〜ConneQt〜の Q のツールと、これから Q に入れるツール（勉強クイズくん・食事記録・ほかの LINE ツール）が、どれを開いても同じように使えるための決まりです。
部品（見た目と動き）の使い方は [README の「Q キット」](../README.md#q-キットq-のツールの共通部品) にあります。ここには「どんな場面で、どう振る舞うか」を書きます。

番号（`A1` など）は、ツールごとに確かめるときの目印です。決まりと違うことをするときは、そのツールの README に理由を書きます。

**対象外**（決まりに合わせない）：ぽもくるの英語の表示（work・break・Volume など）と、ロゴを設定の中だけに置くヘッダー。ジェンダーリビールの Q の名前（決まるまでそのまま）。Rct（Q には入れない）。

---

## A. 名前と見た目

- **A1 見出しの行**：アイコン＋名前（左）、横長のロゴ（右）、その下にキャッチコピー1行（`ls-brand`・`ls-brand-copy`）。名前はひらがな・カタカナ（例：しょくじ）、英字（例：ShoQuji）はロゴと紹介にだけ使う
- **A2 色と字**：ツールの色は1色（`--ls-accent`。濃い色・薄い色・文字色はそこから）。字は Q キットの書体かツールの書体を `--ls-font` で。色を変えられるツール（くろのす・キロっく）は、選んだ色を `--ls-accent` につなぐ
- **A3 暗い表示**：`<html data-ls-dark="auto">`。LINE のトークの見た目（送る前のプレビュー・カードの見本）と、受け取った人が見るお祝いのページは明るいまま
- **A4 部品**：カード・チップ・入力欄・ボタン・開閉・タブ・シート・トーストは Q キットのもの。ツールにしかない見た目（盤・グラフ・こまなど）だけ、ツールの CSS に置く
- **A5 いちばん下**：「📤 ○○を紹介する」と ConneQt のアイコン列（`tool-share.js`）。ページの最後に1つだけ
- **A6 公開の前**：確かめが済むまで `noindex`、ConneQt の一覧とポートフォリオに載せない。アイコン・OGP・`manifest` をそろえる

## B. 開いたとき

- **B1 すぐ出す**：前に開いたときの中身（端末に残したもの）を先に出し、ネットの返事はあとから重ねる。返事を待つあいだ真っ白にしない
- **B2 読みこみ中**：中身と同じ大きさの箱（`ls-skeleton`）か、ボタンの中の「○○中…」。位置がずれない形で。3秒をこえるものは経過秒数と理由（`LineShareUI.progress`）
- **B3 はじめての人**：使い方を3つまで、1回だけ（`LineShareUI.firstTip`。「わかった」で消え、その端末では二度と出さない）。説明の文をページに置きっぱなしにしない
- **B4 前回の続き**：作りかけは端末に残し、次に開いたら「前回の続きから開きました［新しく作る］」
- **B5 電波がないとき**：`sw.js`（`shared/sw-core.js`）で開けるように
- **B6 LINE の外で開いたとき**：送れないことと、できること（「🔑 ログインして送る」「💬 LINE アプリで開く」）を、送るボタンの上に短く。エラーにしない

## C. 入力

- **C1 iPhone**：入力欄は 16px 以上・`appearance: none`・並べるときは `minmax(0, 1fr)`、`html` にも背景色、ぼかし（`backdrop-filter`）は使わない
- **C2 キーボード**：数字は `inputmode="numeric"`／`decimal`、`enterkeyhint` を付ける。入力中は下の送る帯を隠す（Q キットが自動で）
- **C3 選ぶもの**：選んでいるものは `aria-pressed`（`role="radio"` なら `aria-checked`）。押せるところは 44px 以上
- **C4 先に入れておく**：前に入れたもの・よく使うものを、押すだけで入るボタンで出す（例：しょくじの「よく食べるもの」、食事記録の「よく記録するもの」）
- **C5 その場で知らせる**：足りない・まちがいは、その欄のすぐ下に赤い文字で（送ってからまとめて出さない）

## D. 消す・やり直す・確かめる

- **D1 1つを消す**：確かめずにすぐ消し、トーストの「元に戻す」で戻せる（`LineShareUI.toast(…, { actionLabel: "元に戻す", onAction })`）。呼び方は「元に戻す」にそろえる（「取り消す」は使わない）
- **D2 大きな操作**：全部消す・上書きなど元に戻せないものだけ、`LineShareUI.ask({ danger: true })` で確かめる。ボタンの文字は「消す」「上書きする」のように、することを書く（「OK」にしない）
- **D3 ブラウザの小窓は使わない**：`confirm`・`alert`・`prompt` は使わない（LINE の中では上にドメイン名が出る）。代わりに `ask`。コピーできないときは `ask({ readonly: true })` で選べる文字を出す
- **D4 保存の前に聞かない**：変えたらすぐ端末に残す。「保存しますか？」と聞かない

## E. 知らせ

- **E1 トースト**：うまくいった・元に戻せる、は下に数秒のトースト。新しいものが来たら前のは消える
- **E2 失敗**：何が起きたかと、次にすること（「もう一度」「LINE で開きなおす」）を、やさしい言葉で。仕組みの言葉（LIFF・API・GAS・エラーの中身）は出さない。くわしい中身は管理者だけが見られるところ（動作の記録）に
- **E3 待たせない**：保存は返事を待たずに画面に先に出し（薄く）、返事が来たら確定。失敗したら戻して知らせる

## F. 送る（LINE）

- **F1 送り方**：カードは、おくるんのお知らせカード（`OQRN.cardUrl`）か、ツールの Flex を `shareTargetPicker` で。ボタンの文字は「💬 LINEで送る」
- **F2 送る前**：送る内容をトークの見た目のプレビューで見せる。送れない理由はプレビューの上に
- **F3 送ったあと**：「続けて別のトークにも送る」「閉じる」「もう少し作る」（`LineShareUI.afterSent`）。すぐ閉じない
- **F4 カードの末尾**：「Created by ○○ ›」。押すとそのツールが開く。カードを開いたボタンの行き先は、受け取った人が使える場所（作り直す・確かめる）に

## G. ことば

- **G1** やさしい日本語。ひとつの文に、ひとつのこと。「〜してください」より「〜できます」「〜してね」
- **G2** 同じ役割は同じ言葉：「元に戻す」「💬 LINEで送る」「📤 ○○を紹介する」「やめる」「閉じる」「なくてもOK」
- **G3** ボタンは「絵文字＋する言葉」（例：「＋ 記録する」「📷 画像で保存」）。絵文字だけのボタンには `aria-label`
- **G4** 説明の文は短く、必要なときだけ開いて読めるところ（`ls-fold`）に

## H. LINE のボット（トークで使うもの）

- **H1 待たせない**：返事に時間がかかる処理の前に「入力中…」（`/v2/bot/chat/loading/start`）。ただし返事をしない操作（リッチメニューのタブの切りかえなど）では出さない（消えずに残るため）
- **H2 カードの形**：色の帯（小さく日付・区分、太く見出し）→ 中身（大事な数字を先に）→ 行動のボタン（2つまで）。ツールの色を帯に。1通にまとめ、必要なときだけカードを足す（例：未記入があるときだけ「カロリーを入れる」）。LINE が受けつけない書き方（`#RRGGBBAA` の色・`filler`・中身の空の箱）は使わない。横に並べるカード（carousel）は、すべて同じ大きさ（`size`）にそろえる（混ぜると返事ごと断られる）。横に並べると、どのカードもいちばん縦長のカードの高さに引きのばされるので、中身の量がちがうカード（集計と入力のさそいなど）は並べず、別のメッセージにする（1回の返事に5通まで）
  - **カードのボタンは、あとで押されても困らないものだけ**：カードはトークに残り、何日もあとに押されることがある。置いてよいのは、画面（LIFF）・URL を開く／聞き返すだけ（例：「入れる」→「ご飯何杯分？」と聞く）／名前を送って新しく記録する、だけ
  - それ以外（特定の記録・下書きへの操作、期限のある印、承認・取り消しのような1回きり、出題中の答えなど「いまの状態」しだいのもの）はクイックリプライ（H3）だけにし、カードには「👇 下のボタンからえらんでね」と書く
  - 古いボタン・終わった操作が押されても黙らず、「もう入っています」のようにやさしく返す
- **H3 次にすること**：返事の最後のメッセージに、クイックリプライで次の操作（よく使うもの・やめる・画面で詳しく）。13個まで、ラベル20字まで。押したらそのまま終わる操作にする（「次へ」を押させてトークをあふれさせない。例：勉強クイズくんの連続出題）
- **H4 DB にないとき**：記録はしておき、「だいたい」で入れられる選択肢（例：ご飯◯杯分）と「画面で詳しく」を出す。未記入のまま放っておかない
- **H5 カードが通らないとき**：黙らない。文字だけの返事にして、管理者が原因を見られるところに残す（`LAST_LINE_ERRORS` など）。返事の合図（reply token）は1回しか使えないので、断られたあとの返しなおしは push で送る（同じ合図で reply しなおすと「Invalid reply token」でまた断られる）
- **H6 リッチメニュー**：タブは2つまで（例：「📝 記録」と「⚡ よく記録」、「ふだん用」と「出題中用」）。押すとすぐ記録できるものは、ユーザーごとのメニューに。画像の文字は 2500×1686 で読める大きさ
- **H7 送り主**：`sender` の名前とアイコンで、どの機能からの返事かを分ける（増やしすぎない）
- **H8 管理者**：管理者だけの操作（問題の登録・承認など）は、ふつうの人には出さない。見本の文は「入力欄に入れる」（`inputOption: openKeyboard` と `fillInText`）か「コピー」で
- **H9 返事を速く**：1回の呼び出しの中で、同じシート・設定は1回だけ読む（`memo_`）。本人確認などの外への問い合わせは覚えておく

## I. ウィジェット（SQriptable）

- **I1** 小さな画面で、数字や名前を先に。説明は入れない
- **I2** 読めないとき（ネットがない・データがない）は、前の中身を薄く出し、「—」で埋める。エラーの文を出さない
- **I3** 押すとそのツールが開く

## ツールごとの確かめ方

1. このページの番号を上から見て、合っていないところを直す（できないものは README に理由）
2. スマホの幅（390px と 320px）で開き、明るい表示と暗い表示の両方で見る。コンソールのエラーがないこと
3. 主な操作を1通り（作る・直す・消して元に戻す・送る・LINE の外で開く）
4. ボットは、主な返事を偽物の LINE で動かし、カードの形（H2）とクイックリプライ（H3）を見る
